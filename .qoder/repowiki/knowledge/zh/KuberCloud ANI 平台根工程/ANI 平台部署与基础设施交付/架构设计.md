模块按部署目标划分为五个子目录：
- `helm/ani-platform/`：Helm umbrella chart（`Chart.yaml` 声明为 application 类型，通过注解标注组件契约与依赖），`values.yaml` 集中定义全局 namespace、镜像仓库、各基础设施（PostgreSQL/NATS/Redis/MinIO/Milvus/Harbor）的 external mode 接入方式，并通过 `profiles/` 下的 dev、attach-k8s、offline、cluster-validation、gpu-scheduling、instance-foundation、runtime-foundation 等 profile 覆盖 values；`component-contracts/` 存放各组件的 CRD/Contract YAML，作为被依赖方契约。
- `manifests/`：按 M1 阶段切片组织（如 m1-infra-a ~ f、m1-instance-a ~ q、m1-runtime-a、m1-e2e*），每个子目录是一个最小可验证的 Kubernetes 基线或流程契约，文件名以数字前缀保证 apply 顺序，配合各自 README 说明适用场景。
- `docker/`：基于 docker-compose.yml 编排 PostgreSQL、MinIO、NATS、Redis、Milvus+Etcd、可选 Dex/OIDC 与 Attu UI，所有端口绑定 127.0.0.1，供本地开发使用。
- `offline/core-package.yaml` + `core-package-lock.yaml`：离线安装包清单，锁定服务镜像 digest 与 Helm chart 路径，由打包脚本消费。
- `real-k8s-lab/`：面向真实 K8s 集群的 Gate 与 Fixture YAML（含 Rook-Ceph、vCluster、KMS-SM4、生产 Dex、向量存储等），配合 `profile.yaml` 驱动端到端演练。
- `migrations/`：按时间戳命名的 SQL 迁移文件，由外部迁移工具按序执行。
依赖方向单向：Helm Chart 通过 values/profiles 选择 manifests 与 component-contracts；offline 包引用 helm chart 路径；real-k8s-lab 复用同一套契约但注入真实环境参数。
