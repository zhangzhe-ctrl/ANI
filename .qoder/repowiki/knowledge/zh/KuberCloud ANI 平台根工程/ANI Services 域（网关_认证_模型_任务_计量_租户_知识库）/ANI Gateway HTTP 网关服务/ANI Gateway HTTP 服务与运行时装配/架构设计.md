模块以 `main.go` 为唯一入口，使用 CloudWeGo Hertz 启动 HTTP 服务器，并通过一系列 `newGateway*Runtime` 构造函数（如 `storage_runtime.go`、`network_runtime.go`、`k8s_proxy_runtime.go`、`vector_store_runtime.go` 等）按环境变量组装各领域 Provider；所有 Provider 均实现 `pkg/ports` 中定义的接口，由 `internal/router` 通过 `RegisterWithOptions` 集中注入。

- 中间件层 (`internal/middleware`)：在 `chain.go` 中以固定顺序注册 RequestID → Auth → RBAC → RateLimit → Idempotency → Audit，Auth/RBAC 通过 `auth_client.go` 调用外部认证服务或本地 dev 模式，Idempotency/RateLimit/Audit 共享 Redis-backed `GatewayStore`。
- 路由层 (`internal/router`)：每个资源域一个文件（如 `storage_resources.go`、`network_resources.go`），统一遵循 `/api/v1/{resource}` 命名空间，`svc/*` 子路径用于过渡期代理；`router.go` 中的 `RegisterWithOptions` 是路由装配中心，依赖注入 `RegisterOptions` 结构体。
- 运行时装配：顶层 `*_runtime.go` 文件根据 `STORAGE_PROVIDER`、`OBJECT_STORE_PROVIDER`、`WORKLOAD_PROVIDER` 等环境变量选择具体后端（local/minio/kubernetes_rest 等），并返回实现了 `ports.*Service` 接口的实例；未配置时回退为 nil，路由层对可选依赖做降级处理（如 VectorStore、KB gRPC）。
- 依赖方向：main → router → middleware → pkg/adapters/runtime & pkg/ports；模块不直接持有业务逻辑，仅做装配与 HTTP 边界。
