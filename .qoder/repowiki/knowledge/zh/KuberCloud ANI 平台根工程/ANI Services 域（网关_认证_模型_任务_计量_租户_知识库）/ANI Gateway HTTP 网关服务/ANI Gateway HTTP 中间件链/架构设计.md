模块以 Hertz `app.HandlerFunc` 为单位实现各横切能力，由 `chain.go` 中的 `Register(h, store)` 按固定顺序串联：RequestID → Auth → RBAC → RateLimit → Idempotency → Audit，最终到达路由处理器。
- 依赖方向单向：中间件通过 `GatewayStore`（即 `ports.CacheStore`）访问共享缓存用于限流与幂等；通过 `AuthClient` 接口调用远端 auth-service gRPC 服务完成 JWT/API Key 校验与权限检查；不反向依赖业务路由。
- 上下文传递：`auth.go` 将 `tenant_id`/`user_id`/`roles`/`scope` 写入 `RequestContext`，并通过 `types.WithTenant` 注入 Go `context.Context`，供下游 RLS-aware store 使用；`request_id.go` 提供统一的 RequestID 读取。
- 外部依赖抽象：`auth_client.go` 定义 `AuthClient` 接口并由 `grpcAuthClient` 基于 `kubercloud/ani/pkg/generated/pb/auth/v1` 的 gRPC 客户端实现，支持通过环境变量 `AUTH_SERVICE_ADDR` 配置地址并以 2s 超时调用；`store.go` 将缓存存储抽象为 `GatewayStore`，使限流与幂等可插拔。
- 安全边界：`auth.go` 内置白名单路径（`/health`、`/ready`、`/api/v1/auth/*` 等）跳过鉴权；按 scope 隔离平台/租户/sandbox 三类 token 的路由访问；sandbox token 走本地 HMAC 解析，其余走 auth-service。
- 异步审计：`audit.go` 通过带缓冲 channel 将日志条目交给后台 goroutine 落库，不阻塞主请求路径。
