本模块由两个互补目录构成：`repo/services/tasks/` 是任务编排与辅助材料层，`repo/services/docs/` 是权威模块详文层。
- `tasks/execution/` 存放团队任务清单（CORE/SERVICES-TEAM-TASKS）、handler 实现指南与 `TASK-DEPENDENCY-MAP.md`，以 Core/Services 双链 + 批次（A/B/C）+ Sprint 建议组织 Phase 2/3 并行开发顺序。
- `tasks/modules/prd/` 与 `tasks/modules/spec/` 按 `console/`、`boss/` × 业务域（compute/inference/knowledge/alerts/tenant/...）一一对应 `docs/console-modules/`、`docs/boss-modules/` 下的模块详文，命名约定为 `prd-{console|boss}-{module-slug}.md` / `spec-{console|boss}-{module-slug}.md`。
- `tasks/phase2/`、`tasks/phase3/acceptance/` 分别保存各阶段 handler 文档验收与整域联评记录；`tasks/support/` 提供算力/存储/Services 长文辅助。
- `docs/console-modules/` 与 `docs/boss-modules/` 按业务域分目录存放模块主维护源（详文），每个域含 `governance/`（完成矩阵、交付流程、状态看板、gap audit JSON）以及 `openapi-drafts/`（p0/phase3 OpenAPI 草案）。
- 依赖方向单向：PRD/SPEC → 模块详文 → HTML 摘要入口；Phase 验收记录反向引用 `TASK-DEPENDENCY-MAP.md` 中的任务编号，形成“任务→契约→实现”的闭环追踪。
