- 模块产物三件套：每个功能模块对应一份模块详文（`docs/{console,boss}-modules/**/{module}.md`）、一份 PRD（`tasks/modules/prd/prd-{console|boss}-{module-slug}.md`）、一份 SPEC（`tasks/modules/spec/spec-{console|boss}-{module-slug}.md`），slug 保持一致。
- 业务域按 Console/BOSS 两侧平行组织：`docs/console-modules/` 与 `docs/boss-modules/` 下同名子目录（如 compute/inference/knowledge/tenant/health/ops/metering/audit/settings/integration/overview）保持结构对齐。
- 阶段化交付：新增能力先落 `phase2/` 或 `phase3/acceptance/` 验收记录，再回填到 `modules/prd`、`modules/spec` 与 `docs/**` 详文，禁止跳过验收直接写详文。
- OpenAPI 草案集中放在 `docs/console-modules/openapi-drafts/p0/` 与 `openapi-drafts/phase3/`，文件名以 `openapi-phase3-<feature>-draft.md` 形式标注阶段与特性。
- 治理类文档统一置于各域的 `governance/` 子目录，包含完成矩阵、交付流程、状态看板及 JSON 格式的 gate report，作为模块冻结状态的唯一事实来源。
- 所有契约描述必须以 `openapi/v1.yaml` 与兼容性基线为准，禁止在 PRD/SPEC/详文中自造 schema、字段、错误码或路径；待补能力需显式标注「当前未冻结」。
