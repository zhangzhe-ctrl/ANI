模块以契约优先（contract-first）方式组织：
- `openapi/v1.yaml` 定义 ANI Core 基础设施资源（instances、volumes、networks、auth/secrets、metering 等），`openapi/services/v1.yaml` 由 Services 团队独立维护模型仓库/推理/知识库等业务路径，两者通过不同 base path（`/api/v1` vs `/api/v1/svc`）在 Gateway 层路由隔离。
- `proto/` 按业务域划分 gRPC 服务（auth、common、inference、kb、metering、model、task、tenant），每个子目录对应一个 `.proto` 文件；`buf.yaml` 使用 buf v2 管理模块 `buf.build/kubercloud/ani`，启用 STANDARD lint 并放宽 PACKAGE_VERSION_SUFFIX 以兼容 `v1` 包后缀；`buf.gen.yaml` 通过 protoc-gen-go、protoc-gen-go-grpc、protoc-gen-grpc-gateway 将 proto 生成到 `pkg/generated/pb`，并要求实现未实现的 server stub。
- 根目录的 `core-v1-compatibility-baseline.yaml` 锁定 v1 兼容规则（允许新增字段/端点/枚举值，禁止删除路径/方法/required 字段等），并以逐 endpoint 快照形式记录各路径的请求体、响应体、rbac_scope 与参数约束，用于 CI 做向后兼容性校验；`core-alpha-freeze.yaml`、`core-beta-readiness.yaml` 标记发布阶段；`core-contract-changelog-sprint*.md` 记录每次契约变更。
- 依赖方向单向：OpenAPI/Protobuf 是上游契约，被上层 Go/TS/Java/Python SDK 消费，本模块不引入运行时代码。
