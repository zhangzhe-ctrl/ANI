根目录作为 ANI 平台的顶层编排层，不承载运行时代码，而是通过三类工件把各子模块串联：
- 契约层：api_contracts 维护 OpenAPI/gRPC Protobuf 定义，被 sdks（自动生成多语言客户端）、console_frontend（类型安全 HTTP 客户端）和 go_services（网关/服务路由）共同消费；architecture_docs 以 YAML 冻结组件导入与服务边界，作为架构门禁。
- 交付层：deploy_infra 提供 Helm Chart、离线包与 Gate 脚本，按顺序拉起 go_services、ai_rag_engine、console_frontend 及其依赖；validation_scripts 在 CI 中基于同一份 OpenAPI 做契约校验与 live gate 端到端测试。
- 治理层：design_specs 与 development_records 记录产品需求与批次归档，ANI-XX 系列文档构成跨子模块的基线契约，由 .github/workflows、CODEOWNERS 与 CLAUDE.md 统一触发审查与门禁。
子模块之间不直接互相 import，而是通过 api_contracts 暴露的 API 契约以及 shared_pkg 提供的 Ports/Adapters 抽象进行松耦合集成。
