模块以 `server.go` 中的 `Config` 结构体作为配置中心，通过 `MustConnect(cfg)` 顺序初始化 DB/NATS/Redis，再调用 `NewCapabilitiesWithConfig` 将底层适配器（postgresadapter、natsadapter、redisadapter、runtimeadapter、objectstore、vectorstore、gpu、registry 等）按 `ports.*` 接口装配成 `Deps.Ports` 能力集；对外暴露三种启动模式：`RunGRPC`（gRPC + 可选健康探针）、`RunHealthProbe`（仅健康探针）、`RunWorkloadReconcileWorker`（仅 Reconcile 控制器），均基于 `signal.NotifyContext` 实现优雅停机。
- 连接层按职责拆分到独立文件：`db.go`（pgxpool 带重试与版本校验）、`nats.go`（连接+自动创建 ANI_TASKS/ANI_EVENTS 两个 JetStream Stream）、`redis.go`（支持 standalone/sentinel/cluster 三种模式及 URL 解析）。
- 可插拔性集中在 `deps.go` 中多个 `xxxAdapter` 函数（如 `workloadProviderAdapters`、`networkProviderAdapter`、`objectStoreAdapter`、`vectorStoreAdapter`、`imageRegistryAdapter`、`instanceObservabilityAdapter`），根据 `Config` 中的 Provider 字段选择本地或 Kubernetes REST 实现，未配置时返回 NotConfigured 空实现。
- 健康检查由 `probes.go` 的 `probeCheck` 注册表驱动，`dependencyProbeChecks(deps)` 对 postgres/nats/redis/object-store/vector-store/kubernetes-api 执行 Ping/Health，弱依赖失败降级为 degraded，强依赖失败标记 fail；`/metrics` 端点输出 ReconcileController 指标。
- 依赖方向单向向外：本包仅依赖 `pkg/adapters/*` 和 `pkg/ports`，不反向被 adapters 使用，保证所有业务服务通过同一入口获得一致的生命周期管理。
