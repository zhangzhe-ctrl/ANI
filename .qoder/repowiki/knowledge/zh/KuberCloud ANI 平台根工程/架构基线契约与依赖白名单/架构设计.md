本模块不产出可执行代码，而是由 CI/PR 门禁读取的一组 YAML 基线契约，用于约束 ANI Core 与 ANI Services 之间的演进方向：
- `component-import-allowlist.yaml`：定义跨包/跨语言（Go `pkg/*`、Python `services/*`、`ai/*`）允许的直接外部依赖（如 `pgx`、`asyncpg`、`pymilvus`），按耦合等级（`port_required` / `adapter_with_extensions` / `bounded_direct` / `temporary_exception`）分类并附带迁移截止说明；仅列出的路径可突破默认禁止策略。
- `services-boundary-baseline.yaml`：登记 Services 代码对 Core 内部包（如 `pkg/bootstrap`）或 Provider SDK（如 `pymilvus`）的存量例外，标注 owner 与 disposition，防止新耦合扩散。
- `services-contract-baseline.yaml`：冻结当前 Services OpenAPI 中缺失认证声明、异步响应不符合 202+AsyncTask 等规则的 operation_id 级例外，作为契约收敛基线。
- `services-route-baseline.yaml`：登记 Gateway `/api/v1/svc` 路由注册与 OpenAPI 规范之间的已知差异（`code_not_in_spec` / `spec_not_in_code`），新增差异将阻断 PR。
- `inference-service-handler-baseline.yaml`：专门记录阶段 B 推理服务 stub 与实际目标契约在成功状态码上的偏差（200/204 vs 202），实现 handler 时必须同步清理条目。
所有文件统一采用 `version: 1` + `exceptions:` 列表结构，每条异常包含 `status: accepted_baseline`、`owner`、`reason`，必要时附加 `migrate_by` 或 `disposition`，使基线本身成为可审查、可追踪的契约文档。
